# Raksha Bandhan (Rakhi) Campaign Playbook

A reusable guide for running the Rakhi gifting campaign each year. It's based on the 2026 campaign (Aug 6-28, 2026). All 2026 code, pages, ad creatives and Shopify collections were removed on 2026-09-25 because the product line will be different by next year. This file replaces the old plan docs (masterplan, rollback, campaign strategy, creative briefs, combos spec), which are still in git history. To see the exact 2026 implementation, run `git log --all -- shop/rakhi scripts/build-shop.js ads/rakhi`.

## Results that justify doing it again

- Rakhi showed that festivals sell for us. Aug 29, 2026 (the day after the festival, when late orders landed) had the most orders of any single day to date.
- Persona gift guides worked better than a generic "Rakhi sale". People search for "gift for my gamer brother", not "Raksha Bandhan gift".

## Timeline (work back from festival day, F)

| When | What |
|---|---|
| F-5 weeks | Choose personas and pick products for each from the current catalogue. Create the Shopify collections. |
| F-4 weeks | Create the discount codes. Build the catalogue pages. Make the ad creatives. |
| F-3 weeks | Launch the site push and the Meta campaign. Learning phase: don't touch it for 7 days. |
| F-2 weeks | Scale the budget if cost per purchase (CPP) is on target. Add the second batch of persona ads. |
| F-8 days | Peak window: change ad copy to "order by X for delivery before Rakhi" and raise the budget. |
| F-3 days | Final "last chance" copy change. |
| F+1 | Wind down: cut ad spend to a trickle, roll back the site push, check the discounts have expired. |

Set the last safe order date from actual shipping times (print to order plus courier). In 2026 it was F-4.

## 1. Collections (Shopify)

- Create a real Shopify collection for each persona. Then each one has its own URL and can be managed and sorted on its own. Leave them out of the regular `shop/collections/` grid (`HIDDEN_COLLECTIONS` in `scripts/build-shop.js`), so the same products aren't listed twice.
- 2026 personas, for reference only (build next year's from the catalogue as it is then):
  - The Gamer Bro, The Desk Setup Bro, The Car Guy Brother
  - The Aesthetic Sister, The WFH Sister, The Book Worm Sister
  - The Kid Sibling
  - Little Things, Big Feels (under ₹500)
- 4 to 11 products per persona. One product can appear in more than one persona. Dedupe on the "All" page.
- Keep IP-sensitive products (for example, character lamps or licensed-game accessories) out of all paid and catalogue contexts.
- Don't use products that don't exist yet. In 2026, planned items like a cable name tag and a sibling photo frame were never made, so check every handle before writing copy.

## 2. Offers and discounts

2026 tiers (mutually exclusive, only the highest qualifying tier applies):

| Threshold | Offer | Code |
|---|---|---|
| ₹299+ | Free shipping | evergreen, not Rakhi-specific |
| ₹499+ | Free Bunny Keychain (buy X get Y) | `BUNNY499` |
| ₹1,499+ | 5% off | `RAKHI05` |
| ₹2,999+ | 10% off | `RAKHI10` |

**Gotchas:**
- **Shopify doesn't combine an *automatic* buy X get Y discount with an order-level percent-off code.** Make every tier a *code* and have the cart apply the right one itself. If you mix automatic and code discounts, customers can't get both.
- The cart applies the codes automatically, so **never show code names in copy or ads.** Show only the benefit ("5% off ₹1,499+"). Showing a code suggests customers have to type it. In 2026, stale "(code RAKHI05)" text survived on 11 hand-written pages after it was removed from the homepage, so grep the whole site.
- Set `endsAt` on every code to the evening of the festival (2026: ~18:30 UTC on F).
- Inventory tracking is off (everything is printed to order), so a negative stock count on the gift product is fine.
- `FAMILY15` is a relationship discount. Never use it in campaign messaging.

**Cart rewards bar:** a single progress bar in the cart drawer that combines free shipping with the campaign tiers. It auto-adds and removes the free-gift line and shows a Subtotal/Discount/Total breakdown. It lived in `shop/cart.js` (`REWARD_TIERS`, `syncRakhiPerks`, `renderRewardsBar`). Only the free-shipping tier stays after the campaign.

## 3. Site push (what shipped in 2026)

The catalogue itself was built by `scripts/build-shop.js`: `shop/rakhi/` (an "All" page) plus `shop/rakhi/<handle>/` per persona, reusing the standard collection chip strip with `basePath='rakhi'`. The campaign push added these on top:

1. **Sitewide announcement bar** (amber, marquee on mobile), always on and not dismissible. Generated by `announcementBarHtml()` for `shop/**` pages, **and hand-added to about 12 hand-written pages** (index, 404, workshop, enroll, enroll-adult, faq, gallery, connect, policy pages).
2. **Nav link** "Rakhi Gifts" in `index.html`.
3. **Homepage hero takeover**: carousel slides taken from the Rakhi collections, plus Rakhi eyebrow, h1, offer callouts and CTA.
4. **Logo ribbon** "Shop Rakhi Gifts" under the logo, sitewide (`shopHeaderHtml()` plus 14 hand-written pages). This touched more files than anything else in the campaign.
5. **Festive theme** on Rakhi pages only (`body.rakhi-theme`): cream `#FAF8F5` background with a tiled mandala pattern, amber `#E8A020` accents, a "Rakhi Special" badge, and an SVG mandala motif and divider.
6. **Cross-catalogue floating button**: "🪢 Rakhi Gifts" on shop pages and "Shop All Products" on Rakhi pages. A chip in the filter strip was too easy to miss.

**Gotchas:**
- **Hero carousel link paths:** when the carousel data source was switched to Rakhi collections, the slide link template still pointed to `shop/collections/<handle>/`, so every slide 404'd for 5 days. **After any hero, banner or link change, `curl` or click every destination URL.** Checking the visuals isn't enough.
- **Fixed header offsets:** `.shop-header` is fixed, `.header-spacer` is 80px, and `.collection-topbar` is sticky at `top: 80px`. Anything inserted above the header has to adjust all three, on mobile too.
- **Nested anchors:** adding a second link inside the logo `<a>` is invalid HTML. Split it into a `<div class="logo-container">` with two sibling links.
- Hand-written pages don't pick up generator changes. Every sitewide element has to be edited in both `build-shop.js` and each static page, so grep for them.
- Keep the push to things you can switch off. Everything in items 1-6 was designed to come out cleanly at wind-down.

## 4. Ads (Meta)

- **Structure:** one Advantage+ Sales campaign, one ad set, 4 ads at first. Keep it separate from evergreen campaigns (adding ads to those resets their learning phase).
- **Starting 4:** the most specific personas (Gamer Bro, Aesthetic Sister) + the under-₹500 guide (Little Things) + Kid Sibling. Add more in week 2 if the budget allows. Don't run all 9 at once, because ₹77 a day per ad is too little for any ad to finish learning.
- **Budget (2026):** ₹700/day for learning, ₹900 if CPP < ₹280, ₹1,200 in the peak window, ₹200 after the festival.
- **Landing pages:** go straight to the persona collection, with UTMs (`utm_campaign=rakhi2026&utm_content=<persona>`). Never link to the homepage.
- **Copy:** open with the persona's feeling ("Your brother doesn't want another chocolate box."), then name 3 products, then "3D printed in Pune", free shipping and the gift threshold. Change only the last line at each phase change.
- **Checkpoints:** at day 7, pause any ad with zero purchases after its share of spend. Don't judge on days 1-3.

**Creatives:** 1:1 (1080×1080), 4:5 (1080×1350), 9:16 (1080×1920). Top to bottom: persona tag + brand, headline (accent colour on the key phrase), 2×2 product grid with name labels and price badges, offer pills + "Shop now →". Minimum sizes at 1080px: headline 64px, labels 22px. In 2026 these were built as HTML pages and screenshotted to PNG with Playwright (the local server must be running on :8080). Add an offer strip with the benefits only (no code names).

## 5. Wind-down checklist (F+1)

1. Check that all campaign discount codes have expired in Shopify. If the owner extended any, stop and ask before pulling the messaging.
2. Remove the announcement bar (generator + every hand-written copy + CSS), and bring header offsets back to 80px if they were changed.
3. Remove the nav link, homepage promo section and logo ribbon (all pages).
4. Restore the evergreen hero: carousel from regular `collections`, **and** the link template back to `shop/collections/`. Eyebrow "3D Printed Products", h1 "Bringing Ideas to Life Layer by Layer", callouts On Demand Printing / 3D Design / Workshops, CTA "Shop Now" → `shop/`. Curl every slide URL.
5. Cart: remove the campaign tiers and gift-line sync. Keep the ₹299 free-shipping bar.
6. Remove the floating button and the festive theme CSS/vars.
7. Keep the `script.js` `isShop` scroll-padding guard. It fixes an older header-jump bug that has nothing to do with Rakhi.
8. `npm run build-shop`, `npm test`, preview at `http://localhost:8080`.
9. Later, once the catalogue isn't needed: delete the persona collections, the `shop/rakhi/` pages, the generator code and sitemap entries (as done on 2026-09-25).

## Open questions for next time

- Catalogue: seasonal (build in July, remove in September) or year-round gift guides? In 2026 it stayed up for a month after the festival, then was removed.
- Reuse the same push (bar + hero takeover + ribbon), or something lighter?
- Apply this playbook to Diwali and other festivals: same persona-collection approach, started 3 weeks before.
